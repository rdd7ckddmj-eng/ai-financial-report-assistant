# 自选股研究任务队列产品规格

## 1. 一句话定义

自选股研究任务队列允许用户一次输入最多五个六位 A 股代码，按需读取
最新公开日线和近45日官方公告，并用同一套确定性规则安排研究顺序。

它回答的是：

> 我的少量自选公司中，哪几家需要先核查行情异动或最近的官方披露？

它不回答“下一只会涨的股票是什么”，也不生成买卖建议。

## 2. 为什么限制为五家公司

当前产品部署在 Render 免费服务器。一次下载并长期保存全市场数千家公司
的历史行情，会增加内存、请求量、数据源限流和持久化压力。因此第一版采用：

- 用户主动输入自选股；
- 每次最多五家公司；
- 最多三家公司同时核验，单家公司失败不影响其他公司；
- 只保存小型雷达结果，不保存完整全市场行情；
- 页面按需扫描，不要求开发者每天手工更新。

该限制是成本和稳定性边界，不是金融筛选结论。

## 3. 三项确定性证据

所有数字由 Python 使用现有公开行情适配器计算：

1. **涨停候选：** 最新日涨幅达到对应板块和风险警示规则的参考阈值；
2. **明显放量：** 最新成交量达到此前 20 个交易日成交量中位数的 2 倍；
3. **普通换手率历史高位：** 最新普通换手率达到此前最多 250 个有效
   交易日的 90% 历史分位。

普通换手率不等于有效换手率。缺少可核验的时点自由流通股本时，不计算
有效换手率，也不把缺失值当作 0。

## 4. 官方公告证据

每家公司的行情扫描完成后，系统再按需查询近45日巨潮资讯官方公告：

- 只保留发布日不晚于扫描日、且原文链接通过官方域名校验的记录；
- 页面展示最近一条可核验公告的标题、日期、类别和原文链接；
- “高/中/低关注”只由公告标题主题规则生成，不表示利好、利空或影响方向；
- 公告源不可用时，保留已完成的行情研究，不用新闻摘要或 AI 猜测填补。

## 5. 研究优先级

页面不计算数字投资得分，而是使用可解释的三级任务队列：

1. **P1｜立即核查：** 行情端同时触发两项及以上异动证据，或两天内有
   高关注官方公告；
2. **P2｜优先复盘：** 行情端触发一项异动证据，或七天内有高/中关注
   官方公告；
3. **P3｜常规跟踪：** 其他已完成扫描的公司。

同一优先级内，先比较异动证据数量，再比较最近可核验公告距扫描日的天数，
最后按股票代码排序。P1/P2/P3只帮助用户安排复盘顺序，不是投资评分、
上涨概率或估值结论。

## 6. 页面流程

1. 输入以逗号、空格、分号或顿号分隔的六位股票代码；
2. 自动去重、跳过格式错误内容，并明确提示超过五家的部分；
3. 以最多三个并行任务核验公司身份、公开行情和近45日官方公告；
4. 展示成功数量、P1数量、行情触发数量和公告完成核验数量；
5. 展示每家公司的市场数字、触发证据、研究优先级、任务原因和最近官方公告；
6. 一键进入该公司的市场异动 Agent 或公司研究中心继续核验。
7. 下载一份独立中文 HTML 简报，离线保留本次队列、来源、公告链接和失败记录。

## 7. 失败与安全边界

- 单家公司的行情失败时，其他公司继续扫描；
- 并行任务固定上限为三个，不因输入数量继续增加；
- 单家公司的公告源失败时，该公司已核验行情仍然展示；
- 页面不使用旧样例、新闻摘要或 AI 猜测填补实时行情；
- 下载简报只复用页面已经核验的结果，不会再次请求行情或公告；
- 简报对外部文字执行 HTML 转义，只允许通过官方域名校验的公告链接；
- 公告与异动时间接近不能证明因果关系；
- 不在源代码中保存密钥；
- 不保存用户证券账户、持仓或个人交易资料；
- 不构成买入、卖出或持有建议。
