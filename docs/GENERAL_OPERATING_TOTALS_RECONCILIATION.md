# 普通公司营业总收入／营业总成本增强检查（第12批）

本页扩展 `GENERAL_OPERATING_RECONCILIATION.md` 中原先尚未支持的总额版式。原有直接列示营业收入规则继续保留；本次没有修改行业路由、核心收入提取器、单位或容差。

## 核对范围

只有原文明确、按序列示两期营业总收入、营业总成本、成本费用、收益/减值、营业利润、营业外收支和利润总额时，才执行增强关系：

1. 营业总收入 − 营业总成本 + 明确列示的其他收益、投资、公允价值、信用减值、资产减值、资产处置及已出现的汇兑/套期收益 = 营业利润。
2. 原表明确列示的收入子项合计 = 营业总收入（原表没有子项时，不生成这一关系）。
3. 原表明确列示的成本费用子项合计 = 营业总成本。
4. 营业利润 + 营业外收入 − 营业外支出 = 利润总额。
5. 输出收入口径与原文对应行一致。

上面的每条关系都核对本期和比较期。总额版收入、成本费用子项在第一条公式的 `coefficient` 为0；只在单独的子项合计关系出现一次。财务费用下的利息费用/利息收入、投资收益下的联营收益/终止确认收益仍只作为明细证据。负费用参与子项合计时保留负号，负收益/减值损失计入第一条公式时保留负号。不能同时减总成本和营业成本/期间费用。

子项关系的 `scope=explicitly_listed_children` 和 `evidence_keys` 表明只检查原表明确列示的行；不声称披露了所有业务分项，也不假定未列示项目为零。扩展表式一旦出现保险/手续费等同组子项，就要求整组行齐全，删除一条零值行不会自动退回紧凑表式。六项普通成本费用和六项核心收益/减值始终必需。

如果原表只有营业总收入、没有营业收入行，输出一致性使用 `selected_total_operating_revenue`，并明确说明“未宣称其等于营业收入”。只要原文出现营业收入标签，即使其金额损坏，也不允许借用营业总收入。

## 证据不足与矛盾

逐行检查收入至税前利润窗口，不跳过未知科目、零值未知项、重复行、多余数字或损坏数字。凡出现的行都必须有明确两期金额；空白、只有一期、缺失必需行均不补零。汇兑/净敞口套期收益行一旦出现，也必须有明确两期金额。无法完成时保留原有三条税后、归属和输出归母检查，增强层为 `missing_evidence`；四列版式仍为 `unsupported_layout`。

完整取得的总额公式或子项合计出现矛盾时，增强层和整体利润表都为 `mismatch`。现有候选检查因此转入 `needs_review`，输出快照金额与比率不归一化。某个已明确列示的0.00改成非零金额，也不能通过改变行业分类来逃避这条失败路径。

金融公司仍由既有行业适配器决定核对规则。本模块是已有普通公司入口下的附加检查，不以股票代码、公司名或子项金额选择规则；测试固定招商证券和中国平安仍走各自的金融适配器。

跨页仅忽略物理续页首部的明确“公司 + 年年度报告（全文）”页眉和紧接、与物理页码相同的页码行，移除文本另存 `page_headers`。普通业务行、任意整数、母公司标题、页中伪页眉不会被当作页眉删除。
