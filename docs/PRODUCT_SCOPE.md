# 产品定位与覆盖边界

## 平台定位

FANGZHENG AI 金融研究实验室包含两个相互连接的模块：

1. **研究员任务局**：面向零基础学习者，以剧情案件完成“教学、练习、调查、
   证据链、答辩、迁移”的训练，让用户逐步学会阅读材料、控制前视偏差和说明
   判断边界；
2. **公司研究终端**：面向个人投资者、初级分析人员和金融学生，从公司名称或
   股票代码开始，把公开行情、官方公告和年度报告连接成可核验的研究过程，
   并形成附有来源、页码和局限的研究底稿。

两个模块共享同一套证据标准与时间纪律。前者负责培养能力，后者负责把能力
用于真实公开资料；后期开放案件可以要求玩家自行进入公司研究终端寻找证据。
平台不以商业数据库的数据规模或投资预测为目标。

首个跨模块原型只设置一次：玩家从研究员任务局进入 Historical Lens，在一段
真实历史区间中拖动时点滑轨，判断一份官方证据第一次可以进入研究快照的日期。
这种联动用于证明“学到的方法能够迁移到真实资料”，不会被复制成大量同质题目。

《消失的现金》的前两个可玩节点面向零基础用户：先用剧情解释利润看“业务是否
完成”、现金看“钱是否真正收付”，再让玩家同时计算一项业务对利润和现金的
影响；随后进入项目办公室，从6份材料中选出合同、客户验收、年末往来余额和
期后银行回单，组成4环证据链。管理层演示稿和内部聊天是外观可信但证明力不足的
干扰项；一份看似普通的系统运行确认单反而是客户签署的关键外部证据。两个节点
答错都不扣生命，并会更换金额、客户、期限和材料顺序，使用户迁移同一方法，而
不是记住上一题答案。完成办公室证据调查后才解锁 Historical Lens 开放调查。

## 为什么做

上市公司研究的主要摩擦不只是“没有数据”，还包括资料分散、年报篇幅长、
重复计算耗时，以及普通 AI 回答中的数字和结论难以追溯。本产品把寻找资料、
计算指标、提出问题、回到原文核验和整理结果连成一条统一流程。

## 能为用户完成什么

1. 输入公司名称或股票代码，核验上市公司身份并连接公开行情、公告与年报；
2. 用确定性代码计算财务趋势、市场表现、成交、换手和异常指标；
3. 用 Agent 将异常、财务变化、官方披露和历史情境组织为待核验问题；
4. 输出包含关键发现、反方问题、来源链接、PDF 页码和证据缺口的研究底稿；
5. 支持把同一研究框架用于不同公司、年份和历史时点，便于比较与复盘。

## 功能如何关联

网站不把专项功能视为彼此独立的工具，而是按一条研究主线组织：选择标的、
完成公司总览、发现问题、专项核验、形成底稿。研究工作台进一步分为五个集合：

1. **标的发现与跟踪**：每日涨停板观察台、自选股任务队列；
2. **单家公司研究主线**：公司研究中心、一键综合研究 Agent、证据增量 Agent、
   研究结论账本；
3. **市场行为与历史复盘**：K线、成交量与换手率、市场异动、Historical Lens；
4. **财务报表与经营证据**：全市场按需财务快照、年报证据、财务趋势、
   横向比较、财务异常解释；
5. **证据质量与数据扩展**：已核验公司扩展、方法与审计。

用户可以从研究工作台理解各组的用途和建议顺序，再进入具体页面。

证据增量 Agent 解决“第二次回来研究同一家公司时从哪里继续”的问题：首次
核验最近30天官方公告，之后把本机保存的核验日期作为比较起点，只展示该窗口
内的官方披露并按研究问题归类。基准只保存在当前浏览器，不建立用户账户，
也不占用免费服务器的持久化存储。

全市场按需财务快照补足“可以搜索公司”和“少量多年人工核验案例”之间的空档：
用户主动选择公司后，系统临时处理一份最新完整年度报告，勾稽三张报表并输出
五项核心指标、确定性比例、官方链接和 PDF 页码。自动检查通过只代表可以进入
人工复核，不代表已经审计或可以进入多年趋势目录。PDF 不写入数据库，解析后
只在当前会话保留小型结构化结果。

这份小型结果会与一键综合研究 Agent 衔接：同一家公司再次运行综合研究时，
系统先查找逐页核验的多年历史；如果没有，再复用当前会话的单期快照并标记为
“部分证据”。综合研究本身不会重复下载 PDF，也不会把单期候选升级成已核验
数据。这让“搜索标的—发现财务缺口—生成快照—回到综合底稿”成为一条连续流程。

研究结论账本继续完成下一步：用户先写下可证伪的假设、支持条件和失效条件，
系统再把证据增量结果按主题送到相应记录旁边。系统不会从公告标题自动推断支持、
反驳、利好或利空，状态必须由用户看过官方原文后人工确认。最多十条记录保存在
当前浏览器；内容为了页面显示和导出会进入当前应用会话，但不写入服务器数据库。
用户不得填写客户资料、持仓、未公开信息或其他敏感内容。

## 两层覆盖

### A 股按需研究层

- 接受沪、深、北交易所上市公司名称或六位股票代码；
- 按需读取公开日线、官方公告和最近年度报告入口；
- 由 Python 计算行情和财务指标，并保留来源状态；
- 不提前批量下载或永久保存全部上市公司历史资料；
- 公开数据源失败时明确显示缺失，不用旧样例或 AI 猜测填补。

这一层表示“具备按需查询入口”，不表示每家公司都已经完成多年财务审计。

### 已核验深度案例层

当前目录包含贵州茅台、五粮液、泸州老窖、宁德时代、比亚迪和美的集团，
共 21 个财务期间、23 个发布版本。每个案例必须通过统一的身份、年度连续性、官方来源、
年报页码、会计口径和版本检查，才能进入多年趋势与横向比较。

深度目录采用宁缺毋滥的扩展方式：增加公司时先完成证据核验，再公开展示，
不会为了扩大数字而把未经验证的数据标记为已审计。

## 不竞争的范围

本产品不是实时交易终端、商业金融数据库或机构内部研究系统的替代品，不提供：

- 交易所级实时行情与交易执行；
- 受商业授权保护的全量数据库；
- 机构内部路演、持仓、客户或未公开资料；
- 股价预测、上涨概率、选股评分或买卖建议。

## 产品价值

用户得到的不是无法解释的“好或不好”，而是一份知道数字从哪里来、哪些判断
已有证据、哪些问题仍需调查的研究底稿。它能够减少前期资料整理和重复计算，
降低数字抄录、口径混淆和遗漏风险，并让研究更容易复核、比较和复用。

产品的直接效果不是替用户选股，而是缩短从“输入公司”到“形成第一版研究
问题”的时间：用户先看到唯一的当前研究优先级、三类证据状态和下一步核验
问题，再按需进入行情、公告、年报或财务专项页面。

## 产品优势

本产品不以数据规模与 Wind 等商业数据库竞争，优势是透明、低成本、可审计的
研究工作流：

- 官方披露优先，保留公告日期、原始链接、报告版本和 PDF 页码；
- Python 负责数字和固定规则，AI 只基于已核验证据解释和质疑；
- 历史回看隔离未来信息，避免用事后结果改写当时判断；
- 数据不足或单一来源失败时明确展示缺口，不用 AI 猜测补齐；
- 按需读取公开资料，不依赖提前建设昂贵的全量数据库。

这些能力适用于个人上市公司初步研究、研究方法教学和金融科技求职作品展示。
