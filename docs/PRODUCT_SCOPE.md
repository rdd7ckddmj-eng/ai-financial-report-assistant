## 平台定位

FANGZHENG AI 金融研究实验室包含两个相互连接的模块：

1. **《消失的现金》**：面向零基础学习者，以九幕剧情案件完成“入局、教学、
   双钟练习、现场探索、材料研读、交叉核验、证据链、结论答辩与真实历史迁移”
   的训练，让用户逐步学会阅读材料、控制前视偏差和说明判断边界；
2. **研究案件**：面向个人投资者、初级分析人员和金融学生，从公司名称或
   股票代码开始，把公开行情、官方公告和年度报告连接成可核验的研究过程，
   并形成附有来源、页码和局限的研究底稿。

两个模块共享同一套证据标准与时间纪律。前者负责培养能力，后者负责把能力
用于真实公开资料；后期开放案件可以要求玩家自行进入研究案件寻找证据。
平台不以商业数据库的数据规模或投资预测为目标。

首个跨模块原型只设置一次：玩家接受开放委托后先离开案件，自行进入研究案件
工作台寻找能够冻结过去信息截止线的专项研究工具，再在一段真实历史区间中拖动时点
滑轨，判断一份官方证据第一次可以进入研究快照的日期。游戏不会直接标出工具
名称或入口。这种联动用于证明“学到的方法能够迁移到真实资料”，不会被复制成
大量同质题目。

《消失的现金》采用九幕连续流程：01 入局建立代号，02 教学解释利润与现金，
03 在双时钟实验室把六张事实卡归入“利润、现金、两者、本月暂不触发”四个
区域，再把利润—现金差额写成可被材料推翻的调查假设，并为收入边界、应收存在
与期后回款匹配可追溯证据，04 在项目办公室探索文件，05 深读多页材料，06 按
报告日边界交叉核验，07 拼接证据链，08 提交最终判断，09 将时间纪律迁移到
Historical Lens。探索阶段同时设置可信干扰项和外观普通但关键的外部证据；教学
与练习答错不扣生命，也不清空已经正确的工作。双钟归因出错只退回错误事实卡，
假设或调查令出错只退回矛盾项；日期排序不再作为第 03 幕的核心玩法。

九幕不再由同一个匿名人物反复讲解。系统为每一幕设置一位独立角色，分别代表
证据边界、双表思维、时间纪律、现场观察、深度阅读、来源独立、因果链、职业
怀疑和综合表达九项金融研究能力。人物姓名、外观、岗位、语言和页面构图随关卡
变化；最后联合复核时九人同时出现，使角色不是装饰，而是研究方法的记忆锚点。

第 01—08 幕各藏有一件与角色方法相匹配的信物。它们没有任务提示，也不影响
主线通关；玩家必须像密室调查一样主动发现。发现信物后，只有完成当前场景才会
出现信物揭晓页。最终联合复核允许玩家把信物交给对应角色，交付正确才会消耗
信物并解锁一条角色专属思考提醒；交错对象不会消耗。第 09 件信物在真实历史
迁移调查完成后获得。信物、已用提示和关卡一起保存在当前浏览器，不依赖用户名
或 IP。

这套机制训练的不只是金融名词，还包括观察、克制、来源追溯、反事实、可证伪、
不确定性表达和复核责任。角色台词会提醒玩家：被多份材料重复引用的信息不一定
拥有多个独立来源；职业怀疑本身也必须接受证据检验。提示提供检查角度，而不
替玩家给出标准答案。

第八幕是正式结论答辩，三轮分别考查“形成初步结论、守住证据边界、决定核验
行动”，共用三条生命。动态案卷轮换正常时间差、跨期验收、逾期未回款和部分
履约四种情境；每次答错立即换公司、金额、材料和选项，三次失败则退回办公室
领取全新卷宗。这样用户必须迁移证据方法，而不是记住上一题答案。通过三轮答辩
后进入九席联合复核，再解锁跨模块开放调查。

固定案件画面提供“上一步、修改代号、重新开始”三项控制。修改代号不影响当前
关卡或证据；重新开始可选择保留代号并回到教学，或清除代号并回到取名页。这里
刻意不把教学错误计入三条生命：三条生命只约束第八幕正式答辩，规则和失败回退
必须在控制面板与答辩页同时写明，避免用户误以为系统没有执行生命机制。

迁移关不是“找到日期就算完成”。玩家先锁定官方证据第一次可见日，再完成一项
6选1的时间边界判断，同时区分证据公开日、非交易日实际采用的K线日期、下一
交易日和因果限制。错误不会消耗正式答辩的三条生命，但会重新排列选项；只有
日期与解释都正确，系统才把首个案件标记为九幕完整通关。

完整通关后才显示横版“研究员荣誉档案”，并提供一张可下载的 1080×1920
竖版社交海报。第一版没有登录和共享数据库，因此页面只显示“测试赛季·本设备
通关位次”：位次用普通阿拉伯数字（1、10、100），荣誉编号单独保留六位格式
（000001）。它是学习成就纪念，不是全站排行榜，也不代表职业资格、执业许可
或投资能力认证。未来如果接入账号和数据库，只替换位次数据源，不改变通关规则。

## 为什么做

上市公司研究的主要摩擦不只是“没有数据”，还包括资料分散、年报篇幅长、
重复计算耗时，以及普通 AI 回答中的数字和结论难以追溯。本产品把寻找资料、
计算指标、提出问题、回到原文核验和整理结果连成一条统一流程。

## 能为用户完成什么

1. 输入公司名称或股票代码，核验上市公司身份并连接公开行情、公告与年报；
2. 用确定性代码计算财务趋势、市场表现、成交、换手和异常指标；
3. 用 Agent 将异常、财务变化、官方披露和历史情境组织为待核验问题；
4. 输出包含关键发现、反方问题、来源链接、PDF 页码和证据缺口的研究底稿；
5. 支持把同一研究框架用于不同公司、年份和历史时点，便于比较与复盘。

## 功能如何关联

网站不把专项功能视为彼此独立的工具。用户输入公司后会创建或恢复同一家公司的
一份“研究案件”，首页始终先回答五件事：

1. 当前最值得核验的问题是什么；
2. 已经有什么证据；
3. 哪些证据互相矛盾；
4. 还有什么未知；
5. 下一步应该去验证什么。

综合研究、年报人工复核、Historical Lens、行情和公告等专项页面只负责向同一
案件提交有版本检查的 CasePatch。用户离开专项页面再返回时，看到的是更新后的
同一份五问与证据底稿，而不是另一份互不关联的答案。没有登记矛盾只表示“当前
尚无可引用的矛盾记录”，不能写成“证据没有矛盾”或“信息完全一致”。

研究案件按“选择标的—形成初步问题—专项核验—更新五问—形成底稿”的主线
组织。左侧五个集合只是专项视图的导航分组：

1. **发现研究对象**：每日涨停板观察台、自选股任务队列；
2. **完成公司初研**：公司身份与概览专项研究工具、一键综合研究 Agent；
3. **调查市场事件**：K线、成交量与换手率、市场异动、Historical Lens；
4. **核验财务证据**：按需财务快照、年报证据、财务趋势、财务异常解释、
   横向比较；
5. **跟踪与治理研究**：证据增量 Agent、研究结论账本、负责任 AI 与控制、
   已核验公司扩展。

用户可以从研究案件理解各组的用途和建议顺序，再进入具体页面。案件、证据引用、
假设和审计记录保存在当前浏览器的独立键 `wfz.research_cases.v1`，与游戏存档、
自选股和最近浏览记录互不覆盖。存储有案件数量、单案大小、总大小和 revision
边界；旧标签页不能静默覆盖较新的研究进度。

证据增量 Agent 解决“第二次回来研究同一家公司时从哪里继续”的问题：首次
核验最近30天官方公告，之后把本机保存的核验日期作为比较起点，只展示该窗口
内的官方披露并按研究问题归类。基准只保存在当前浏览器，不建立用户账户，
也不占用免费服务器的持久化存储。

全市场按需财务快照补足“可以搜索公司”和“少量多年人工核验案例”之间的空档：
用户主动选择公司后，系统临时处理一份最新完整年度报告，勾稽三张报表并输出
五项核心指标、确定性比例、官方链接和 PDF 页码。营业收入、净利润、经营现金流、
总资产和总负债分别保留自动提取原值、原单位、会计口径、PDF 页码和短原文摘录。
用户必须逐项选择“确认原值”“修改并说明原因”或“驳回并说明原因”；五项决定
完成前不能导出该份单期人工复核底稿，也不能把该快照写成已核验证据或用它推动
案件 readiness。自动检查通过只代表可以进入人工复核，不代表已经审计或可以进入
多年趋势目录。PDF 不写入
数据库，解析后只在当前会话保留小型结构化结果。这一限制只约束该份财务快照，
不代表每个研究案件都必须先完成年报复核；案件正式导出始终只按规范化
`ready_to_export` 派生规则判断。

完成决定后的结构化复核结果会与一键综合研究 Agent 和研究案件衔接：同一家公司
再次运行综合研究时，
系统先查找逐页核验的多年历史；如果没有，再复用当前会话的单期快照并标记为
“部分证据”。综合研究本身不会重复下载 PDF，也不会把尚未完成人工决定的单期
候选升级成已核验数据。这让“搜索标的—发现财务缺口—生成快照—逐项复核—回到
同一案件”成为一条连续流程。

Historical Lens 使用独立的历史案件范围：`as_of_date` 和实际采用的有效交易日
写入后不可向未来移动；只有发布日期不晚于截止日的证据可以进入案件。用户主动
揭示的后来 1/3/6 个月行情只用于事后复盘，不会写回“当时可知”的证据与结论。

正式完整研究工作底稿只在案件派生状态达到 `ready_to_export` 后开放：五条专题
研究泳道均已启动，首页已有真实证据引用、明确下一步，且没有等待人工复核的
artifact、evidence 或 hypothesis。导出保留公司与时点范围、首页五问、专题问题、
来源 URL、公告日期、PDF 页码、原值/单位/口径、复核状态、紧凑分析产物、假设、
未知、矛盾和审计日志，并把事实、推断与未知分开。导出不包含 PDF 或二进制本体；
空矛盾列表也不会被转换成“没有矛盾”的确定性陈述。

研究结论账本继续完成下一步：用户先写下可证伪的假设、支持条件和失效条件，
系统再把证据增量结果按主题送到相应记录旁边。系统不会从公告标题自动推断支持、
反驳、利好或利空，状态必须由用户看过官方原文后人工确认。最多十条记录保存在
当前浏览器；内容为了页面显示和导出会进入当前应用会话，但不写入服务器数据库。
用户不得填写客户资料、持仓、未公开信息或其他敏感内容。

## 两层覆盖

### A 股按需研究层

- 接受沪、深、北交易所上市公司名称或六位股票代码；
- 按需读取公开日线、官方公告和最近年度报告入口；
- 由 Python 计算行情和财务指标，并保留来源状态；
- 不提前批量下载或永久保存全部上市公司历史资料；
- 公开数据源失败时明确显示缺失，不用旧样例或 AI 猜测填补。

这一层表示“具备按需查询入口”，不表示每家公司都已经完成多年财务审计。

### 已核验深度案例层

当前目录包含贵州茅台、五粮液、泸州老窖、宁德时代、比亚迪和美的集团，
共 21 个财务期间、23 个发布版本。每个案例必须通过统一的身份、年度连续性、官方来源、
年报页码、会计口径和版本检查，才能进入多年趋势与横向比较。

深度目录采用宁缺毋滥的扩展方式：增加公司时先完成证据核验，再公开展示，
不会为了扩大数字而把未经验证的数据标记为已审计。

## 不竞争的范围

本产品不是实时交易终端、商业金融数据库或机构内部研究系统的替代品，不提供：

- 交易所级实时行情与交易执行；
- 受商业授权保护的全量数据库；
- 机构内部路演、持仓、客户或未公开资料；
- 股价预测、上涨概率、选股评分或买卖建议。

## 产品价值

用户得到的不是无法解释的“好或不好”，而是一份知道数字从哪里来、哪些判断
已有证据、哪些问题仍需调查的研究底稿。它能够减少前期资料整理和重复计算，
降低数字抄录、口径混淆和遗漏风险，并让研究更容易复核、比较和复用。

产品的直接效果不是替用户选股，而是缩短从“输入公司”到“形成第一版研究
问题”的时间：用户先看到唯一的当前研究优先级、三类证据状态和下一步核验
问题，再按需进入行情、公告、年报或财务专项页面。

## 产品优势

本产品不以数据规模与 Wind 等商业数据库竞争，优势是透明、低成本、可审计的
研究工作流：

- 官方披露优先，保留公告日期、原始链接、报告版本和 PDF 页码；
- Python 负责数字和固定规则，AI 只基于已核验证据解释和质疑；
- 历史回看隔离未来信息，避免用事后结果改写当时判断；
- 数据不足或单一来源失败时明确展示缺口，不用 AI 猜测补齐；
- 按需读取公开资料，不依赖提前建设昂贵的全量数据库。

这些能力首先服务于个人上市公司初步研究与研究方法教学，也可以作为金融科技
能力展示；后者不决定产品功能或研究边界。
